# Argus v2 PRD

## 1. 문서 상태
- 이 문서는 Argus v2의 목표 상태를 정의하는 PRD입니다.
- 현재 구현이 이미 이 문서를 만족한다는 뜻이 아닙니다.
- 다음 구현 라운드의 제품 판단 기준은 이 문서를 우선합니다.
- 현재 동작, 기존 라우트, 기존 데이터 흐름은 `doc/architecture/`, `doc/domains/`, `doc/reference/` 문서를 함께 확인합니다.

## 2. 제품 정의

### 제품 한 문장
Argus v2는 한국장 상황을 장 시작 전과 장중에 빠르게 판독하기 위한 시장 상황판입니다.

이 제품은 뉴스 피드, 범용 금융 대시보드, 종목 추천 서비스가 아닙니다. 핵심 질문은 `무슨 일이 있었나`가 아니라 `지금 시장 상태가 어떤가, 왜 그렇게 볼 수 있는가, 무엇이 바뀌면 판단이 바뀌는가`입니다.

### 핵심 해석 공식
Argus v2는 시장을 아래 순서로 읽습니다.

1. 파생/옵션 포지셔닝을 먼저 본다.
2. 실제 뉴스/매크로 트리거가 그 포지션을 설명하거나 반박하는지 본다.
3. 지수, 수급, 섹터 같은 시장 반응이 그 결론을 확인하거나 약화시키는지 본다.

뉴스와 파생 데이터를 항상 억지로 엮지 않습니다. 연결 근거가 있을 때만 연결하고, 근거가 부족하면 독립 신호로 둡니다.

## 3. 사용자와 사용 순간

### 핵심 사용자
- 한국 주식시장을 매일 확인하는 개인 투자자
- 초급에서 중급 사이의 시장 이해도를 가진 사용자
- 뉴스량보다 오늘 장의 방향, 위험, 전환 조건을 빠르게 알고 싶은 사용자
- 옵션/파생 신호를 시장 판단의 중요한 근거로 보는 사용자

### 핵심 사용 루틴
- 장 시작 전: 30초 안에 오늘 시장 결론을 형성한다.
- 장중: 수시로 확인하며 결론이 바뀌었는지, 왜 바뀌었는지, 다음에 무엇을 봐야 하는지 1분 안에 파악한다.

### 첫 화면이 반드시 답해야 하는 질문
- 오늘 한국 시장은 `강한 상방 / 상방 우위 / 중립 / 하방 우위 / 강한 하방` 중 어디에 가까운가?
- 지금 가장 중요한 변수는 무엇인가?
- 시장 결론을 바꿀 정도로 의미 있는 섹터나 테마가 있는가?

## 4. 제품 원칙
- 정보량보다 판단 구조가 중요합니다.
- 첫 화면은 압축되어야 하며 카드가 난립하면 안 됩니다.
- AI는 별도 탭이 아니라 각 화면 안의 해석 레이어입니다.
- 매수/매도 같은 액션 추천 언어를 쓰지 않습니다.
- 데이터 지연, 대체소스, 미수신 상태를 숨기지 않습니다.
- 데이터 신뢰도가 낮아지면 AI 확신도도 같이 낮아져야 합니다.
- 국내 시장 MVP이므로 상승은 빨강, 하락은 파랑을 사용합니다.
- MVP는 데스크톱 우선입니다. 모바일은 이후 최적화합니다.
- 화면 톤은 리서치 데스크의 명료함과 관제판의 빠른 판단성을 결합합니다.
- Argus v2 디자인 기준은 밝은 리서치 데스크 배경, 얇은 격자감, 직각에 가까운 카드, 검정 결론 축, 빨강/파랑 방향성 강조입니다.
- 큰 라운딩, 다크 그라디언트, 장식적 금융 앱 톤은 피하고 한 화면 판독성을 우선합니다.

## 5. 정보 흐름

### 기본 판단 흐름
1. 시장 전체 결론
2. 시장 결론을 보정하는 섹터/테마
3. 이후 확장 단계에서 관심종목 또는 개별 종목

### MVP에서 제외하는 흐름
- 관심종목 중심 사용 흐름
- 개인화된 종목 위험 알림
- 종목별 매수/매도 의사결정
- 원문 뉴스 피드를 탐색하는 뉴스 앱형 흐름

## 6. 핵심 변수
Argus v2는 아래 변수를 병렬 위젯으로 나열하지 않고 하나의 시장 판단으로 조합합니다.

- 지수와 지수선물
- 해외 시장
- 매크로 변수
- 수급
- 파생/옵션
- 뉴스와 트리거 이벤트
- 시장 결론을 보정할 정도의 섹터/테마

## 7. MVP 화면 구조

### 상단 탭
1. 시장 판단
2. 옵션·선물
3. 현물 반응
4. 뉴스 트리거

`AI 인사이트`는 별도 탭으로 두지 않습니다. AI 해석은 필요한 화면에 내장합니다.

`관심종목`은 MVP 탭에서 제외합니다. 기존 구현에 관심종목 경로가 남아 있더라도 v2 MVP의 핵심 범위는 아닙니다.

### 시장 판단
시장 판단은 첫 화면이며 아래 네 구역만 가집니다.

1. 시장 결론
2. 파생/옵션 압력
3. 시장 반응
4. 오늘의 트리거

대시보드의 목적은 상세 분석이 아니라 30초 판독입니다. 상세 표, 원문 링크, 긴 설명은 아래 영역이나 상세 탭으로 보냅니다.

### 옵션·선물
목적은 시장 참여자들이 실제로 어느 방향으로 포지션을 잡는지 확인하는 것입니다.

포함 범위:
- 외국인 KOSPI200 선물 순매수/순매도
- 기관/개인 선물 수급
- 베이시스
- Put/Call Ratio
- 미결제약정 변화
- 근월물 중심 ATM/OTM 주요 행사가
- 옵션 레벨 지도
- 만기별/행사가별 상세 확장 여지

### 현물 반응
목적은 파생/옵션 중심 결론을 실제 시장 가격과 내부 흐름이 확인하는지 검증하는 것입니다.

포함 범위:
- 코스피, 코스닥, KOSPI200 선물
- 상승/하락 종목 수
- 외국인/기관/개인 현물 순매수 거래대금
- 거래대금과 시장 체력
- 의미 있는 섹터 강세/약세
- 시장 결론을 약화하거나 강화하는 반응

현물 수급은 현물 반응을 검증하는 보조 입력입니다. KOSPI200 선물 수급 endpoint가 확인되지 않은 상태에서 현물 수급을 선물 수급 필드에 대입하지 않습니다.

### 뉴스 트리거
목적은 시장 결론에 영향을 준 실제 뉴스, 매크로, 정책, 산업 이벤트를 확인하는 것입니다.

포함 범위:
- 밤사이 매크로 이벤트
- 금리/FOMC/연준 발언
- 환율/달러/원화
- 미국 증시와 SOX 반도체
- 원자재
- 한국 정책/정부 발표
- 공시
- 산업/섹터 뉴스
- 지정학/중국 이슈

뉴스는 기사 단위 피드가 아니라 이벤트 단위로 묶고, 화면에는 시장 결론의 근거 또는 독립 트리거로 노출합니다.

## 8. 시장 결론 모델

### 표면 라벨
- `강한 상방`
- `상방 우위`
- `중립`
- `하방 우위`
- `강한 하방`

### 내부 계산 개념
내부적으로는 long/short pressure 개념을 사용할 수 있지만, 사용자 표면에서는 매수/매도 액션처럼 보이는 표현을 피합니다.

### 예시 문장
`외국인은 KOSPI200 선물을 매도하고 있고 풋 미결제약정도 증가해 하방 우위입니다. 밤사이 금리 상승 뉴스도 위험자산에는 부담입니다. 다만 반도체 강세가 유지되면서 지수 낙폭은 제한되고 있어 강한 하방으로는 번지지 않고 있습니다.`

## 9. AI 해석 요구사항
주요 결론 화면은 아래 요소를 지원해야 합니다.

- 현재 결론
- 핵심 근거
- 반대 근거
- 전환 조건
- 오늘 체크할 지표
- 확신도
- 데이터 신뢰도

AI는 결론을 내야 하지만 확신이 낮은 상황을 숨기면 안 됩니다. 상충 신호가 크면 결론을 중립 쪽으로 완화하고, 어떤 근거가 서로 충돌하는지 보여줘야 합니다.

## 10. 데이터 신선도와 신뢰도

### 목표 신선도
- 지수/선물: 1분 이내
- 옵션/OI: 3~5분 이내
- 중요 뉴스: 가능하면 즉시 반영
- 일반 뉴스: 배치 반영 가능
- FRED 같은 매크로 reference: 공표 주기 기준 최신값

### 표시 원칙
- 주요 지표 옆에 source와 업데이트 시각을 작게 표시합니다.
- 지연, 대체소스, 미수신은 강하게 표시합니다.
- 마지막 수신값이 있으면 지연 표시와 함께 보여줍니다.
- 대체 소스를 사용하면 source를 명시합니다.
- 결론 계산에서는 오래되거나 빠진 데이터의 가중치를 낮춥니다.
- 데이터 공백을 빈칸으로 숨기지 않습니다.

## 11. 파생·옵션 데이터 모델

### 핵심 신호
- 외국인 KOSPI200 선물 순매수/순매도
- 베이시스
- Put/Call Ratio
- 미결제약정 변화
- 기관/개인 선물 수급

KOSPI200 선물 등락률은 여전히 유용하지만, 핵심 우선순위는 포지션과 옵션 압력입니다.

### 옵션 저장 전략
- MVP 화면은 근월물 중심의 ATM/OTM 주요 행사가를 먼저 보여줍니다.
- DB는 만기별 + 행사가별 전체 옵션 체인으로 확장 가능해야 합니다.
- 단발 snapshot이 아니라 장중/일별 누적 시계열을 저장합니다.
- 현재 구현은 SQLite SQL migration 기반이며, `derivatives_option_chain_snapshots`, `derivatives_option_chain_levels`, `derivatives_source_status`를 옵션 체인/행사가/수신 상태의 기준 테이블로 둡니다.

### 저장 주기
- 핵심 데이터: 1분 단위 snapshot
- 무거운 옵션 체인: 3~5분 단위 snapshot
- 일별 집계: 장 마감 후 생성

### 옵션 레벨 지도
상세 탭은 아래 정보를 지원해야 합니다.

- 콜 OI 밀집 행사가
- 풋 OI 밀집 행사가
- 전일 대비 OI 급증 행사가
- 현재 지수와 가까운 주요 레벨
- 상단 저항/하단 지지 해석
- 만기별 차이

대시보드에는 현재가 근처 주요 상단/하단 레벨과 급증 레벨만 압축해서 보여줍니다.

## 12. 뉴스·매크로 모델

### 수집과 분류
뉴스/매크로는 넓게 수집하고 좁게 노출합니다.

분류 대상:
- 금리/FOMC/연준 발언
- 환율/달러/원화
- 미국 증시
- 원자재
- 한국 정책/정부 발표
- 공시
- 산업/섹터 뉴스
- 지정학/전쟁/중국 이슈

### cockpit 노출 기준
대시보드에는 시장 영향이 큰 트리거만 올립니다.

뉴스 선택 점수는 아래 요소를 봅니다.

- 뉴스 중요도
- 관련 시장 반응
- 영향 섹터
- 지속 가능성

### 인과관계 원칙
- 뉴스와 파생을 항상 엮지 않습니다.
- 연결할 근거가 있을 때만 연결합니다.
- 연결 강도는 `강함 / 보통 / 약함 / 불명확`으로 표시합니다.
- 근거가 약하면 `관련 가능성` 수준으로 표현합니다.
- `이 뉴스 때문에 이 수급이 나왔다` 같은 단정은 금지합니다.

## 13. 시장 반응 레이어
시장 반응은 파생/옵션 중심 결론이 실제 가격과 내부 흐름에서 확인되는지 검증하는 레이어입니다.

확인 질문:
- 가격 흐름이 파생/옵션 압력을 확인하는가?
- 시장 폭이 넓어지는가, 좁아지는가?
- 강한 섹터가 지수를 버티게 하는가?
- 뉴스는 실제 시장 반응으로 이어졌는가, 아니면 헤드라인에 그쳤는가?

## 14. 섹터/테마 처리

### 내부 고정 추적 섹터
- 반도체
- 2차전지
- 바이오
- 자동차
- 조선
- 방산
- 금융
- 인터넷·게임
- 전력·원전·전선

### 노출 원칙
- 핵심 섹터는 계속 추적합니다.
- 대시보드에는 시장 결론을 바꿀 정도로 중요한 섹터만 올립니다.
- 섹터는 독립 랭킹 콘텐츠가 아니라 시장 판단을 보정하는 근거입니다.

## 15. 알림과 설정

### 알림
MVP는 화면 안 경고/전환 배지만 제공합니다.

대상:
- 외국인 선물 매도/매수 급변
- 풋/콜 OI 급증
- 주요 옵션 레벨 이탈
- 중요한 뉴스 트리거 발생
- 시장 결론 전환

브라우저 알림, 텔레그램, 카카오, 문자 등 외부 알림은 MVP 이후 확장입니다.

### 설정
- MVP에는 무거운 설정 화면을 두지 않습니다.
- 좋은 기본값을 먼저 설계합니다.
- 상세 탭에서 만기, 행사가, 기간 필터 정도만 제공합니다.
- 개인화 배치, 관심 변수 선택, 경고 임계값 커스터마이징은 나중 범위입니다.

## 16. 상태와 예외 처리

### 로딩
- 대시보드는 먼저 결론 영역의 skeleton을 보여주고, 데이터가 들어오는 순서대로 구역을 채웁니다.
- 일부 데이터가 늦어도 전체 화면을 막지 않습니다.

### Empty
- 데이터가 없으면 왜 없는지와 어떤 대체 지표를 봐야 하는지 설명합니다.
- `-` 또는 빈칸으로 의미 있는 공백을 숨기지 않습니다.

### Stale
- 지연 데이터는 마지막 값과 지연 상태를 같이 표시합니다.
- 결론 확신도와 데이터 신뢰도에 반영합니다.

### Conflicting signals
- 결론은 냅니다.
- 확신도는 낮춥니다.
- 상충 근거를 명확히 표시합니다.
- 충돌이 크면 결론을 중립 쪽으로 완화합니다.

## 17. MVP 성공 기준
- 장 시작 전 30초 안에 오늘 시장 결론을 이해할 수 있습니다.
- 장중 1분 안에 결론 변화와 이유를 확인할 수 있습니다.
- 파생/옵션 데이터가 누적 저장되고 전일/장중 변화가 보입니다.
- 뉴스/매크로 이벤트가 시장 결론의 근거 또는 독립 트리거로 정리됩니다.
- 첫 화면의 핵심 판단 구역은 데스크톱 첫 viewport 안에 들어옵니다.

## 18. 검증과 테스트 원칙
테스트는 중요하지만 제품 개발을 잡아먹으면 안 됩니다.

우선 검증 대상:
- 시장 결론 라벨 계산과 표시
- 데이터 freshness/fallback 처리
- 데이터 신뢰도와 AI 확신도 하락
- 상충 신호 처리
- 대시보드 네 구역 렌더링
- 핵심 옵션/파생 snapshot 저장 계약

과하게 하지 않을 것:
- UI 스타일 snapshot 남발
- 세부 copy 전체 고정
- 모든 뉴스 분류 케이스 exhaustive test
- 제품 판단이 정리되기 전 과도한 테스트 매트릭스

## 19. MVP Out Of Scope
- 관심종목
- 매수/매도 추천
- 개인화 알림
- 모바일 우선 최적화
- 일반 섹터 랭킹판
- raw 뉴스 피드 중심 화면
- 근거 없는 AI 인과관계 연결
- 모든 데이터의 완전 실시간화

## 20. 구현 영향
- Argus v2는 PRD 기준 clean-room 경계에서 새로 구현합니다.
- 기존 KRX 화면/집계 코드는 제거했습니다.
- 기존 KIS/FRED/NAVER/DART/provider 코드는 자동 재사용 대상이 아니라 참고 자료입니다.
- 실데이터 smoke test와 데이터 계약 검증을 통과한 provider만 v2 runtime에 연결합니다.
- UX, IA, 데이터 조합 계층은 v2 기준으로 다시 설계합니다.
- 현재 구현 문서는 `doc/plans/current-status.md`와 `doc/plans/argus-v2-roadmap.md`를 기준으로 관리합니다.
