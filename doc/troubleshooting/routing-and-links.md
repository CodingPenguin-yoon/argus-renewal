# Routing And Links

## 왜 이 작업이 필요했나
화면 이름은 `대시보드`, `AI 인사이트`, `매크로 캘린더`로 바뀌었는데 주소는 예전 이름인 `overview`, `macro`, `global-events`를 계속 쓰고 있으면 제품이 덜 정리된 느낌을 줍니다.

## 왜 주소를 새 이름으로 바꿨나
주소도 사용자 표면의 일부이기 때문입니다. 북마크, 공유 링크, 운영 문서, 테스트 모두 같은 언어를 써야 혼란이 줄어듭니다.

새 canonical 주소는 다음과 같습니다.
- `/krx/dashboard`
- `/krx/insights`
- `/krx/macro-calendar`

## 왜 예전 주소를 완전히 지우지 않았나
예전 주소를 바로 없애면 기존 북마크나 링크가 깨질 수 있습니다. 그래서 옛 주소는 새 주소로 자동 이동시키는 redirect만 남겼습니다.

- `/krx/overview` -> `/krx/dashboard`
- `/krx/macro` -> `/krx/insights`
- `/krx/global-events` -> `/krx/macro-calendar`

## query param은 왜 그대로 살렸나
`매크로 캘린더`에는 `다음 24시간`, `이번 주` 같은 세부 탭이 있습니다. 이런 링크가 깨지면 사용자가 원하는 화면으로 바로 들어가지 못합니다. 그래서 `?tab=next-24h` 같은 정보도 같이 넘기도록 했습니다.

## 이상할 때 체크할 것
- 예전 주소로 들어가도 새 주소로 자동 이동하는지 확인합니다.
- `매크로 캘린더` 세부 탭 링크가 이동 후에도 유지되는지 확인합니다.
- 테스트에서 canonical 경로와 redirect 경로를 혼동하고 있지 않은지 확인합니다.
