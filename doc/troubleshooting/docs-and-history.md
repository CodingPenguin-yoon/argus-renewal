# Docs And History

## 왜 문서를 다시 정리했나
문서가 많아지면 “현재 사실”과 “과거 계획”이 섞이기 쉽습니다. 그러면 실제 코드와 문서를 같이 봐도 무엇이 최신인지 헷갈립니다.

## 왜 폴더를 나눴나
역할이 다른 문서를 분리하려고 했습니다.

- `architecture`: 지금 코드가 실제로 어떻게 되어 있는지
- `domains`: 뉴스, 매크로 캘린더 같은 도메인별 상세
- `plans`: 진행 상태와 해결 로그
- `reference`: 참고 설계와 자료
- `troubleshooting`: 쉬운 설명 문서

## 왜 쉬운 설명 문서를 따로 만들었나
아키텍처 문서는 개발자 기준으로 써야 정확합니다. 대신 “왜 이런 결정을 했는지”를 이해하기 쉬운 문서는 별도로 두는 편이 더 낫습니다. 그래서 이번 변경 배경은 `troubleshooting/`에 따로 모았습니다.

## 앞으로 어디를 보면 되나
- 현재 구조가 궁금하면 `architecture/`
- 지금 남은 일이 궁금하면 `plans/`
- 도메인 운영 방법이 궁금하면 `domains/`
- 오늘 왜 이렇게 바꿨는지 궁금하면 `troubleshooting/`

## 이상할 때 체크할 것
- 현재 사실 문서와 과거 계획 문서를 섞어 읽고 있지 않은지 확인합니다.
- 문서에 적힌 경로가 실제 화면 주소와 같은지 확인합니다.
- `troubleshooting/` 문서가 최신 상태를 반영하는지 확인합니다.
