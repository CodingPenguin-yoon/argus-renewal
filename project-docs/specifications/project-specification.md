# 프로젝트 명세: Argus Market Data Terminal

- 상태: `APPROVED`
- 최종 검토일: `2026-07-22`
- 최종 승인자: 사용자

이 문서는 승인된 새 제품 방향이다. 기존 `argus_v2` 코드의 동작은 첫 수직 기능을 검증하는 동안 유지하며, 레거시 코드 삭제는 characterization test 이관과 별도 승인 후 수행한다.

## 1. 해결할 문제

- 현재 문제: 필요한 시장 수급, 대형주, 선물·옵션 정보가 여러 증권사와 화면에 흩어져 있고 공급자별 데이터 성격이 다르다.
- 필요한 이유: 사용자는 장중에 한국 시장의 주도 수급과 대형주 반응을 짧은 시간 안에 확인해야 한다.
- 성공했을 때: 코스피·파생시장 수급, KOSPI200 구성종목의 외국인·기관 수급, 핵심 종목 차트를 한 화면 체계에서 공급자와 신선도를 확인하며 조회한다.

## 2. 사용자와 사용 흐름

| 대상 | 목표 | 현재 어려움 | 주요 사용 흐름 |
|---|---|---|---|
| 한국 시장을 매일 보는 개인 투자자 | 시장 주도 주체와 핵심 종목 반응 파악 | 데이터가 여러 증권사 화면에 분산 | 시장 전체 확인 → KOSPI200 구성종목 스캔 → 종목 상세 확인 |
| 파생 신호를 함께 보는 사용자 | 현물과 선물·옵션 수급 비교 | 현물·파생 데이터의 단위와 갱신 시점이 다름 | 코스피 수급 → 선물·콜·풋 수급 → 옵션체인 확인 |

## 3. 목표

- 시장 전체 수급과 대형주 종목별 수급을 같은 시간·단위 체계로 제공한다.
- 장중 추정치와 장 마감 확정치를 구분해 표시하고 저장한다.
- 화면은 사용자의 판단에 필요한 가격, 수급, 거래량, 차트, 신선도만 우선 제공한다.
- 특정 증권사 장애가 전체 제품 장애로 번지지 않도록 공급자 실패를 격리한다.
- 기존 Argus v2를 유지한 채 새 수직 기능을 하나씩 검증하고 전환한다.
- API key 없이도 운영 경로와 같은 저장·조회 흐름을 검증하도록 `mock` data mode를 먼저 제공한다.

## 4. 비목표

- 종목 매수·매도 추천 또는 자동주문
- 장중 투자자 분류를 거래소 확정치처럼 표현
- 모든 국내 종목·모든 파생상품을 첫 단계에서 수집
- 공급자 수치를 근거 없이 평균하거나 조합해 가짜 단일 수치 생성
- 초기 단계의 대규모 분산 시스템 또는 DB 교체
- 뉴스와 AI 해석을 핵심 시장 데이터보다 먼저 확장

## 5. 제품 범위

### 포함

1. 시장 개요
   - KOSPI, KOSPI200 시장 상태
   - 개인·외국인·기관 현물 수급
   - KOSPI200 선물·콜옵션·풋옵션 수급
   - 공급자, 관측 시각, 신선도, 추정·확정 상태
2. KOSPI200 구성종목
   - 거래일에 적용되는 KOSPI200 universe와 구성 기준일
   - 현재가, 등락률, 거래량·거래대금
   - 장중 외국인·기관 수급
   - 장 마감 개인·외국인·기관 확정 데이터
3. 종목 상세
   - 가격 차트
   - 외국인·기관 수급 시계열
   - 장 마감 투자자별 수급 이력
4. 파생 상세
   - KOSPI200 근월 선물
   - KOSPI200 옵션체인과 주요 행사가
   - 삼성전자·SK하이닉스 개별주식 파생은 API 검증 성공 시 포함

### 상단 정보구조

상단 navigation은 다음 세 영역으로 고정한다.

1. `대시보드`
   - KOSPI·KOSPI200 시장 상태와 현물 수급 요약
   - KOSPI200 선물·콜·풋 수급 요약
   - 외국인·기관 순매수, 수급 급변, 거래대금 상위 종목
2. `종목`
   - KOSPI200 구성종목의 시세·거래대금·장중 수급 테이블
   - 종목 상세 상단에 현재가 요약을 고정
   - 상세 본문은 `차트 | 수급`으로 구분
3. `파생`
   - 내부 구분은 `KOSPI200 | 삼성전자 | SK하이닉스`
   - KOSPI200은 선물·옵션체인·투자자 수급을 제공
   - 삼성전자·SK하이닉스는 live API로 확인된 파생상품만 활성화

## 8. 핵심 업무 규칙

- `estimate`와 `confirmed`는 같은 값의 상태 변경이 아니라 서로 다른 관측 fact로 보존한다.
- `observed_at`은 공급자가 의미하는 시장 시각이고 `collected_at`은 Argus 수집 시각이다.
- 공급자 데이터가 오래되면 마지막 값을 유지할 수 있지만 반드시 `stale`로 표시한다.
- 개인 수급이 장중 API에 없으면 추정해서 생성하지 않는다.
- 서로 다른 거래소 범위(KRX, NXT, 통합)와 단위를 변환 없이 합산하지 않는다.
- 1차 구현에서는 시세와 수급의 `market_scope`를 `KRX`로 통일하며 NXT·SOR 통합은 후속 범위로 둔다.
- `confirmed`는 KRX 장 마감 거래실적을 기준으로 생성하고, 증권사 장중값을 장 마감됐다는 이유만으로 확정값으로 승격하지 않는다.
- 여러 공급자 값이 충돌하면 우선순위 규칙과 원본을 노출하며 조용히 평균하지 않는다.
- KOSPI200 universe는 거래일 중 임의로 변하지 않고 승인된 기준일 데이터가 갱신될 때 교체한다.
- `mock`과 `live` fact는 같은 조회에서 혼합하지 않으며 화면에 DEMO 여부를 명시한다.

## 9. 외부 제약과 의존성

- KIS, LS증권, 키움 REST API의 계정·신청·호출 제한과 이용약관을 따른다.
- 증권사 장중 투자자 수급은 거래소 확정치가 아닐 수 있다.
- 실시간 WebSocket 시세와 REST 장중 수급 조회는 별도 신선도 정책을 가진다.
- 초기 저장소는 기존 SQLite를 유지하며 실제 데이터량 측정 후 재검토한다.

## 10. 실패와 경계 조건

- 인증 실패: 해당 공급자만 unavailable로 기록하고 시크릿을 오류에 포함하지 않는다.
- 호출 제한: 공급자별 backoff와 다음 실행 시각을 기록한다.
- 부분 응답: 누락 필드를 기록하고 완전한 데이터로 위장하지 않는다.
- 중복 요청: idempotency key 또는 DB unique contract로 중복 저장을 차단한다.
- 장외 시간: collector별 세션 정책에 따라 skip하고 이유를 기록한다.
- 추정치 정정: 새 관측 fact로 저장하고 최신 선택 규칙으로 조회한다.
